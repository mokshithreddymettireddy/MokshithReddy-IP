Question 1 - Online Symposium Portal

Given HTML Structure

<form action="/register" method="POST">
    <input type="text" name="name">
    <input type="email" name="email">
    <button>Submit</button>
</form>

1. Missing HTML5 Semantic Elements

  • <header>
  • <main>
  • <section>
  • <footer>
  • <label> for each input field

2. Standards-Compliant Structure

<header>
   <h1>College Symposium Registration</h1>
</header>

<main>
   <section>

      <form action="/register" method="POST">

         <label>Name</label>
         <input type="text" name="name" required>

         <label>Email</label>
         <input type="email" name="email" required>

         <button type="submit">Submit</button>

      </form>

   </section>
</main>

3. HTTP Request Interpretation

The browser sends an HTTP POST request to /register. The student's name and email are sent securely inside the request body instead of appearing in the URL.

4. HTTP Response Cycle

Step Description
1 User submits the form.
2 Browser creates an HTTP POST request.
3 Server validates and stores the registration details.
4 Server sends an HTTP response (200 OK / 201 Created).
5 Browser displays the confirmation page.

5. Usability & Accessibility Improvements

  • Add labels for all input fields.
  • Use placeholders.
  • Use required validation.
  • Add aria-label attributes.
  • Display success/error messages.
  • Use HTTPS.

Question 2 - Cross-Browser Compatibility Issue

Given HTML

<html>
   <head>
      <title>Company</title>
   </head>
   <body>
      <div>
         <h1>Welcome
         <p>About us
      </div>
   </body>
</html>

1. Errors

  • Missing </h1>
  • Missing </p>
  • Improper nesting

2. Browser Interpretation

Modern browsers automatically insert missing closing tags. However, older browsers may display inconsistent layouts, causing rendering differences.

3. Missing Semantic Elements

  • <header>
  • <main>
  • <section>
  • <footer>

4. Correct W3C-Compliant HTML

<!DOCTYPE html>

<html>

<head>
   <title>Company</title>
</head>

<body>

<header>
   <h1>Welcome</h1>
</header>

<main>

<section>
   <p>About us</p>
</section>

</main>

</body>

</html>

5. Cross-Browser Compatibility Techniques

  • Validate HTML using W3C Validator.
  • Use semantic HTML5 elements.
  • Use CSS Reset or Normalize.css.
  • Test in Chrome, Firefox, Edge and Safari.
  • Avoid deprecated HTML tags.
  • Use responsive CSS layouts.

Question 3 - Form Submission Failure

Given Configuration

<form action="/submit" method="GET">

   <input type="text" name="username">

   <input type="password" name="password">

   <button type="button">Login</button>

</form>

1. Issues

  • Button type is button instead of submit.
  • GET method exposes username and password in the URL.
  • Password transmission is insecure.

2. Why HTTP Request Is Not Triggered

The button type is button, which performs no action. Only a button with type="submit" automatically submits the form.

3. Role of GET Method

  • Sends data through the URL.
  • Suitable for searching and filtering.
  • Not suitable for passwords or login forms.

4. Correct Implementation

<form action="/submit" method="POST">

   <label>Username</label>
   <input type="text" name="username" required>

   <label>Password</label>
   <input type="password" name="password" required>

   <button type="submit">
      Login
   </button>

</form>

5. Secure Data Transmission

  • Use POST method.
  • Enable HTTPS.
  • Hash passwords before storing.
  • Use CSRF protection.
  • Validate user input.
  • Implement secure session management.

Conclusion

This assignment demonstrates the practical application of HTML5, semantic elements, HTTP request-response communication, form submission, browser compatibility, and secure web development practices. Following W3C standards improves accessibility, security, maintainability, and ensures that web applications work consistently across different browsers and devices.
