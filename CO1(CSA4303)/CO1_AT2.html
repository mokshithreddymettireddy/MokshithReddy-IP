Question 1 : HTTP Response Analysis

Given Header

HTTP/1.1 200 OK
Date: Mon, 01 Apr 2026 10:00:00 GMT
Content-Type: text/html
Content-Length: -150
Connection: keep-alive

1. Invalid Fields

  • Content-Length: -150 is invalid because Content-Length cannot be negative.
  • Other header fields are syntactically correct.

2. Issue with Content-Length

Content-Length specifies the number of bytes in the response body. A negative value is invalid and may cause browsers to reject the response, terminate the connection, or fail to load the webpage correctly.

3. Status Code Analysis

Status code 200 OK indicates a successful response. However, because the header contains an invalid Content-Length value, the response is technically incorrect.

4. Corrected Header

HTTP/1.1 200 OK
Date: Mon, 01 Apr 2026 10:00:00 GMT
Content-Type: text/html
Content-Length: 150
Connection: keep-alive

Question 2 : DOM Structure Analysis

Given DOM

<html>
   <head>
      <title>Test Page</title>
   </head>
   <body>
      <div>
         <p>Hello World
      </div>
   </body>
</html>

1. Missing Elements

  • Missing closing tag </p>

2. Browser Interpretation

Modern browsers automatically insert the missing closing tag and repair the DOM before rendering.

3. Rendering Impact

  • Usually displays correctly.
  • Fails HTML validation.
  • May cause unexpected CSS or JavaScript behaviour.

4. Corrected Code

<div>
   <p>Hello World</p>
</div>

Question 3 : GET vs POST in Login System

Method Example Visibility Security
GET /login?user=admin&pass=1234 Visible in URL Low
POST /login Hidden in Request Body Moderate

1. Difference

  • GET sends data through the URL.
  • POST sends data inside the request body.

2. Suitable Method

POST is preferred because credentials remain outside the URL, making it more secure for authentication.

3. Risks of GET

  • Password visible in URL.
  • Stored in browser history.
  • Recorded in server logs.
  • Can be shared accidentally.

4. Best Practices

  • Use POST.
  • Enable HTTPS.
  • Hash passwords.
  • Use secure sessions.
  • Implement CSRF protection.

Question 4 : HTML Code Inspection

Given Code

<!DOCTYPE html>
<html>
<head>
<title>Sample</title>
</head>
<body>
<h1>Welcome
<p>This is a paragraph
<img src="image.jpg">
</body>
</html>

1. Missing Closing Tags

  • </h1>
  • </p>

2. Issues with Image Tag

  • Missing alt attribute.
  • Image may not load if path is incorrect.

3. Browser Behaviour

Browsers automatically close missing tags and attempt to display the page normally, but HTML validation fails.

4. Corrected HTML

<h1>Welcome</h1>

<p>This is a paragraph.</p>

<img src="image.jpg"
alt="Sample Image">

Question 5 : Browser-Server Communication Flow

Step Description
1 User enters website URL.
2 DNS converts the domain name into an IP address.
3 Browser sends an HTTP request.
4 Server processes the request.
5 Server returns the HTTP response.
6 Browser renders the webpage.

Possible Delays

  • DNS lookup
  • Slow Internet
  • Server processing time
  • Large files
  • Browser rendering
Performance Optimizations
  • DNS caching
  • Browser caching
  • Compress files using GZIP
  • Use a CDN
  • Optimize images
  • Keep HTTP connections alive
  • Minify CSS and JavaScript
